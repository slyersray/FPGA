# 开发前待澄清问题清单

## 已确认信息

以下内容视为当前基线，本清单不再重复提问：

1. 本项目只开发两个模块：加密模块、压缩模块。
2. PCIe 不在开发任务内。PCIe IP 的集成、驱动、板级连接，以及 PCIe IP 占用的资源，都不计入本项目范围，也不计入资源指标。
3. 两个模块按内部总线设计：1024 bit、400 MHz。外部 PCIe 由客户侧现成 IP 承担。
4. 目标平台为 “Agliex-7, AGI x027.022”。目标板为现成开发板，形态与官方 Agliex-7 I-serial 基本相同。开发用 EDA 与 license 由开发方自备。
5. 加密算法范围为 AES-256 与 SM4，客户可以提供 C 语言比特级参考模型。
6. 压缩对象为 16 bit BF16 的多维 Tensor。处理方向包括简单无损压缩（原文举例哈夫曼）以及基于矩阵运算的变换并量化到 4 bit。输入速率目标 400 Gbps，压缩后速率降到 1/2 或 1/4。
7. 资源只统计上述两个模块：单模块占所用 FPGA 资源不超过 25%～30%，两个模块合计的逻辑资源控制在 50%～60% 以内。分母是整片 FPGA 的资源总量，不含 PCIe 及其他系统逻辑。

## 待澄清问题

**Q01 完整订货号与资源总量**

“Agliex-7, AGI x027.022”。请客户提供官方版本名称，或者能否直接提供datasheet

**Q02 两个模块在系统中的位置**

请确认加密与压缩是串联在同一条 1024 bit 通路上，还是两个独立模块。若串联，请指定顺序。请确认两个模块是否必须同时工作，并同时达到 400 Gbps。

**Q03 400Gbps性能要求**

- 400 MHz 是硬约束，还是在达到 400 Gbps 的前提下可以调整
- 指标针对每个模块单独测量，还是两模块同时开启时的链路测量

**Q04 资源验收的单一上限**

- 加密模块上限为30%
- 压缩模块上限为30%
- 两个模块合计上限60%

仍需客户确认：
- 统计阶段：综合后还是布局布线后
- 统计对象：逻辑、寄存器、块存储、DSP 是否分开设限
- 两个模块之间的互连逻辑记入合计，还是两边各自吸收

**Q05 压缩算法要做成哪一种**

哈夫曼类无损，以及矩阵变换加 4 bit 量化，压缩率写 1/2 或 1/4。请逐项确认 (拿到客户C模型前要先做资源评估)：

- 两种都要做且可切换，还是只做其中一种
- 1/2 和 1/4 都要支持，还是达到其中一档即可
- 矩阵变换的类型、块大小、系数由谁提供
- 4 bit 的数值格式、缩放因子粒度（per-tensor 或 per-block， block粒度形状？）
- 无损路径在压不到目标比率时的行为：原样输出、报错，还是允许更低压缩率
- 有损路径的误差上限（用哪一种指标、阈值是多少）

**Q06 Tensor 形状**

请确认 (拿到客户C模型前要先做资源评估)：

维度数、每一维的上限、内存布局、对齐要求，以及形状是编译期固定还是运行时变化。
BF16 在 1024 bit 总线上的字节序定义。

**Q07 加密模式与方向**

请确认 (拿到客户C模型前要先做资源评估)：

- AES-256 的工作模式，以及 SM4 的工作模式
- 只做加密？还是需要考虑解密？
- 片上是两条算法同时存在且可切换，还是同一时刻只综合一种
- 密钥、IV 或计数器的加载方式和位宽
- 分组对齐、填充和尾包规则
- SM4 按标准 128 bit 密钥实现？

**Q08 模块接口**

- 需要确认加密模块 数据输入/输出接口及协议， 配置输入接口？
- 需要确认压缩模块 数据输入/输出接口及协议， 配置输入接口？

**Q09 系统结构**

- 已澄清项目包含PCIe / serdes； 是否包含MCU进行boot以及必要驱动实施？如果是，FPGA 模块测试时可以考虑使用。

**Q10 验收边界**

客户要求在开发板上连续稳定工作不少于 24 小时。该项依赖 PCIe 与板级系统，不在两个模块的开发任务内。请客户确认本项目验收边界为：

- 两个模块和客户部分集成后 FPGA板级压测超过24小时；测试执行由客户负责
- 我方提供2个模块的FPGA实现代码以及测试代码、测试结果

**Q11 交付物**

两个模块的 RTL 源码、模块级仿真环境、综合与实现工程、时序报告、资源报告、端口说明。交付物不包含 PCIe 工程、驱动和整机测试。
